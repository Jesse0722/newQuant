# T02 证券证据与审计可靠性实施计划

> **执行方式：** 主管按任务顺序分派实现，规格与代码质量分别独立审查。

**目标：** 修复已复现的证券分母、数值判断及证据工件误放行，使数量匹配和来源绑定分别可见。

**架构：** 保留现有离线只读审计。严格验证 CSV 后再筛选证券，新增轻量证据 manifest 绑定输入与原件，CLI 独占创建完整报告对。不改业务表、源修复计划或历史审计，不自动获取外部数据。

**技术栈：** Python 3.11、标准库 CSV/JSON/SHA256、SQLAlchemy 只读事务、pytest。

## 已复现问题

1. 指数、空代码或非法代码可进入显式 A 股分母；未知证券类型和未上市却交易的状态被静默排除。
2. 数值字段先经 float 检查，OHLC 却比较原始值；TEXT 价格及 BOOLEAN 可错误通过。前收/涨跌幅、零量额及量额均价矛盾未报告。
3. 范围外指数等记录能稀释 A 股异常率。
4. CSV 解析与哈希读取两次文件；原件变化可造成证据不匹配。
5. JSON/Markdown 输出覆盖既有文件；第二次写入失败可形成混合报告对。

## 任务 1：输入及数值审计

文件：`backend/app/services/market_data_quality_service.py`、`backend/tests/test_market_data_quality.py`。

- 单次读取 CSV 字节用于解析和 SHA；拒绝重复/空表头、缺字段及行宽不匹配。
- 明确证券类型 `a_share/index/fund/bond/other`，规范六位代码及交易所；A 股还需符合当前支持规则。未知类型、重复及 `is_trading=1,is_listed=0` 拒绝，不自动修正输入。
- 服务入口校验日期与显式证券集合，不将部分日期缺失静默降级为主数据代理。资格标记必须为布尔真并绑定归一化证券集合摘要。
- 只在审计层拒绝布尔数值、归一化数值后比较 OHLC 与前收/涨跌幅；不改变旧修复批次的数值/来源兼容策略。
- 量额配对与归一化单位均价矛盾明确报告，禁止金额指标；保留 `scoring_allowed` 作为覆盖/核心字段门槛的原有语义，增加窗口级 `amount_metrics_allowed`。
- 异常率分母使用实际观测的 A 股证券集合，范围外非 A 股不得稀释异常率。

先写临时数据库/CSV 复现测试确认失败，再最小实现并运行审计、来源、修复相关测试。

## 任务 2：轻量证据绑定

新增纯离线 `backend/app/services/market_universe_evidence_service.py` 及独立测试；由任务 1 实现者顺序完成。

- manifest 版本 `market-universe-evidence-v1`，显式文件 SHA；声明 `full_market_point_in_time/security_subset`、`retrospective`、日期、市场和分母口径。
- 绑定证券清单/控制文件的实际字节 SHA；来源保留 ID、HTTPS URL、包内原件路径、原件 SHA、带时区的观察时间和定位信息。
- 证券清单来源与控制来源 ID、URL、原件不得相同；这只是重复证据拦截，不能自动证明统计独立性或权威性。
- 全市场资格要求 SH/SZ/BJ 范围、所审日期覆盖、同口径控制来源绑定及全部原件核对；局部范围、缺 manifest 或仅数量匹配不具备评分资格。没有完整证券池仍禁止评分。
- 不生成历史证券清单，不解释公告，不添加生命周期事件数据库/通用 compiler。两证券官方材料仍为局部证据，不能替代全市场停复牌或点时分母。

验收：合法合成完整证据 fixture 可验证结构门槛；局部/缺证据、字节篡改、原件缺失、范围/口径错误、控制来源重用均不得误放行。合成 fixture 不作为真实全市场验收。

## 任务 3：CLI 与报告工件

文件：`backend/scripts/audit_market_data_quality.py`、独立 CLI 测试。

- 新增 manifest 与显式 SHA 参数，缺一、无证券清单或无控制文件时拒绝；旧参数保留诊断用途。
- 完整序列化 JSON、渲染 Markdown 后，独占创建两个 0600 文件；任一已有、竞争或写入失败不覆盖旧文件，只清理本次拥有的新建文件。退出码保留 0/1/2。
- 输出分别呈现数量匹配、证据绑定、范围资格及金额门槛；错误不打印连接凭据。

先验证已有 JSON/MD、第二文件失败、竞争、输入字节变化及 CLI 真/假质量退出码，再实现与交叉审查。

## 集成与验收

## 兼容与撤销

没有 manifest 的旧 CSV 继续生成诊断报告，但不能单凭匹配总数取得全市场资格；既有审计报告不修改。输出文件不能复用旧前缀。撤销本轮只读报告时删除新前缀文件即可；不需要数据库备份、迁移或回滚。来源原件的哈希只绑定内容，不能证明内容真实，也不能证明资料在历史当时已可得。
