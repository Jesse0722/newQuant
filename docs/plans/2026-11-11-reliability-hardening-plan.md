# P1/P2 可靠性治理实施与验收清单

日期：2026-11-11。用户已确认优先可靠性，并授权本轮集中处理审查和 TODO 中的 P1/P2，要求完成测试验证。

## 范围与分工

- 后端核心：监控最新窗口/历史截止、指标最小样本、源失败语义、事务漏写、任务终态、交易输入/提醒幂等/复盘/回测口径。
- AI/消息：单条事务隔离、demo/ignored/dismissed 下游隔离、严格结构与原文支持、来源/反证策略、固定离线评测、审计/幂等、映射与默认关闭流水线。
- 前端：研究对象与异步结果绑定、分页/深链、弱网恢复、通知二期、候选证据、驳回理由、分包与隔离浏览器回归。
- 主管集成：Python 3.11 锁定环境、增量迁移/真实 PG、行情原始身份保护、CI/发布备份恢复、文档、交叉审查、重启及提交。

每组独立修改边界；主管复核规格与证据，再交叉审查事务、并发、数据安全及接口兼容。审查新发现纳入同轮修复和对应回归。

## 验收门槛

1. 后端全量默认测试通过，外部服务用 mock；真实 PG 在独立随机测试库/schema 验证迁移、JSON/日期/约束、并发 claim、备份及升级后的旧备份恢复。
2. 前端 lint/build、完整隔离 Playwright 通过。浏览器不连接真实业务 API，覆盖核心工作流、乱序返回、弱网/存储故障和证据复核。
3. 旧结构升级后 ORM 无漂移，旧行保留；SQLite/PG 回滚命令有可重复测试，未知旧结构拒绝自动 stamp。
4. CI 检查先于发布，发布 SHA 与被检查 SHA 一致；维护窗口前备份，失败恢复旧数据与镜像，不能只测试空库恢复。
5. 本地后端在迁移及备份核对后重启并只读探活；数据不足不能用测试通过替代质量放行。
6. 代码、已验证事实、运行限制与外部待办分别记入 TODO 和实施报告；最后提交本轮改动。

## 保留边界

- T01 作为 PostgreSQL 验收前置纳入；T02 继续作为行情数据门槛。
- T07 历史行情的真实修复、权威上市/退市/停牌及证券代码有效期不能靠合成测试完成；保留现有冻结/备份/来源约束，不编造数据，不默认启用收费来源。
- 公网服务端认证 T03、市场状态 T27–T30、P3 扩展不计为本轮完成。
- 按股账本继续保留，增加明确口径；不自动猜测历史交易的计划归因。事件后验收益不包装为可执行策略权益曲线。
- 新消息定时采集与 LLM 默认关闭；本轮不自动部署 ECS 或开启付费调用。
