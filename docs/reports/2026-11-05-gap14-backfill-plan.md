## 分阶段执行

### 小样本闸门

下一次获准启动整日回补后，先分别选择最多 10 只沪市、10 只深市和 5 只北交所证券，对完整 14 日做 T08 `fetch` 和只读 `plan`。每个市场单独快照、单独计划，明确传入代码，不使用省略 `--codes` 的全清单模式。

这些 pilot 的具体代码尚未单独冻结，整日回补不在本次执行范围；启动时需明确具体代码和获准写入范围。冻结的全清单与分块是范围证据，不是自动执行授权，scope JSON 的规则也不能替代人工审核或 CLI 校验。

先核对来源、返回身份、日期、OHLC、前收与涨跌幅关系、量额单位和异常状态。北交所尤其要确认历史代码与返回代码的一致性，不能未经点时映射擅自改码。任何空响应、部分返回、错误或不支持先保留并核查；不能把停牌、新上市或源失败一概当作漏数，也不能用零价格填补。

只有明确可用的候选行才进入人工核对、完整备份和应用。源全部失败不得继续；`partial` 不能自动按成功应用。若缺行有独立的合法不交易证据，应保留在原冻结清单的状态说明中，再生成范围明确的有效子计划，不通过缩减分母抬高覆盖率。

### 受控分批

大范围回补按每市场最多 500 只、同一 14 日区间划分。冻结工件定义沪市 5 个、深市 6 个、北交所 1 个逻辑块，共 12 个块；每块最多 7,000 单元，可按错误率、审核能力与维护窗口继续缩小。不能将三个市场全部作为一次 78,036 单元任务执行。

每批使用以下流程：

1. 检查无其他写库任务，确认唯一主库和前批验证状态；冻结本批代码清单及哈希。
2. 选择明确的一个来源采集正式不复权行情，保留原始快照和请求结果。
3. 生成只读差异，保持 `allow_clear_optional=false`；核对代码、日期、条数、来源、单位及 SHA256。对这 14 个原整日缺口，本类回补计划应只有新增或无变化；出现更新、删除意图或来源冲突即停止并单独评审。
4. 使用 T08 CLI 按已核对文件 SHA 执行，自动完整备份后再同事务写入行情和逐行审计。不要直接调用 T06 全市场写入 API。
5. 保存批次 ID、备份清单、审计与主键变化核验，运行 `verify` 和同截止日的 T02，再决定是否继续下一批。

小样本已经写入的代码应从后续待插入目标中明确排除或计为无变化，不能自动更新重叠行情。来源不可用时，暂停该市场/逻辑块；若评审后改用另一来源，生成新的完整单源快照与计划，不拼接同一行的不同来源字段。

单批命令形状如下，代码清单必须来自获准逻辑块，输出路径必须唯一：

```bash
python scripts/repair_daily_quotes.py fetch \
  --source baostock --from-date 20261019 --to-date 20261105 \
  --codes <明确核对的逗号代码清单> --max-target-rows 7000 \
  --output <私有目录中的唯一来源快照.json>
```

北交所应使用单独获准的 `--source akshare` 快照，不把 BJ 代码送入 BaoStock 后忽略 unsupported 结果。后续 `plan/apply/verify/rollback` 命令与风险见[修复手册](../daily-quote-repair.md)。

## 验收与暂停条件

批次验收与全市场评分门槛分开：前者检查本批审计、写入主键、新值、单位、备份和无范围外改动；后者需要独立点时分母及全窗口质量。T02 能成功生成报告、没有新增范围外异常且本批验收通过，才可继续后续批次；全局 `scoring_allowed=false` 不应被伪改为 true，也不意味着不能继续有审计的补数。

最终不能仅以“14 日不再为空”宣布完整恢复。逐日需报告冻结代理清单中的返回数、核心有效数、量额完整度、缺失、空响应、失败、不支持及待核查代码。T06 的当前目标有效覆盖 95% 只是代理清单诊断口径，不能替代真实市场覆盖率；残余目标必须留痕，不得静默丢弃。

如任一批出现计划外改动、审计或备份不一致、明显价格/量额错配，停止后续写入，保留现场，先核对再恢复。已完成批次不会因后续失败自动撤销；确需全部恢复时按审计链逆序批次回滚，禁止按日期批量删除。

所有缺口处理后仍需独立历史证券池、上市退市/停牌资料和逐日控制总数，才可能放行全市场评分。当前方案没有采购新服务、修改主数据或执行这 14 日的任何回补。
